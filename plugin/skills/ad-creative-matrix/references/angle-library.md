# Angle library: hooks, bodies, CTAs and the screening rubric

Working material for `ad-creative-matrix`. Everything here is a structure to fill with the
user's real facts. Nothing in this file is a claim, a figure or an example to copy.

---

## 1. Hook angles (aim for about five hooks per angle)

Fifty hooks written from one angle are one hook reworded fifty times. Spread them across angles,
then vary the wording inside each angle.

| Angle | What the hook does | Shape to fill in |
|---|---|---|
| Pain | Names the problem in the viewer's own words | "[Specific frustration] again?" |
| Cost of inaction | Makes the price of waiting concrete | "Every [period] without [fix] means [specific loss]" |
| Outcome | Leads with the end state | "[Result] without [the usual sacrifice]" |
| Specificity | Uses a number, a name, a timeframe the user supplied | "[Exact detail] in [exact timeframe]" |
| Proof | Opens on evidence the user can show | "[Verifiable result] at [named customer, with permission]" |
| Contrarian | Challenges a belief the audience holds | "Everyone says [belief]. Here is where it breaks." |
| Curiosity gap | Withholds one piece, never the whole point | "The [thing] most [role] overlook in [situation]" |
| Identity | Speaks to a role or situation, not a personal attribute | "For [role] who [situation]" |
| Question | Asks something the viewer already asks themselves | "Why does [common situation] keep happening?" |
| Objection | Answers the doubt before it forms | "Not another [category] that [common failure]" |

Rules for every hook:

- Specific beats abstract. A number, name or detail the user supplied beats an adjective.
- **Never assert a personal attribute of the viewer** (health, finances, age, ethnicity, religion,
  sexuality and similar). Platform ad policies restrict this, and the exact wording of the rules
  changes, so check the platform's current policy when a hook gets close to the line.
- Identity hooks name a role or a situation ("for facility managers handling two sites"), never
  a trait.
- No claim the user cannot back. Hooks that imply a result need a source before they go live.
- Each hook stands alone and works with every body, so it must not depend on a particular
  second sentence.

### Hook formats by medium

| Medium | The hook is | Write it as |
|---|---|---|
| Static image or document ad | The first line of the primary text plus the image headline | Both lines, so they work together or alone |
| Video or UGC | The first 3 seconds | A spoken line, an on-screen text line, and one shot description |
| Carousel | Card one | The card-one headline and the promise it makes about card two |

## 2. The five bodies ("meat")

Each body is a different structure, not a different length. A body begins in a way that follows
any hook without a seam: no "And that is why" openers, no pronouns pointing at a hook.

| ID | Structure | Use it when | Needs from the user |
|---|---|---|---|
| B1 | Problem, agitate, solution | The pain is felt and familiar | The problem in plain words, the consequence, the fix |
| B2 | Before and after | The change is visible and easy to picture | A real before and a real after |
| B3 | Proof led | There is a case, number or testimonial that can be shown | Verified result, named source, permission to use it |
| B4 | How it works | The product is new or hard to picture | Three steps or fewer, in the viewer's terms |
| B5 | Objection and myth | The buyer arrives with a known doubt | The real objection, the honest answer |

If the user lacks the input for a structure (no verified proof for B3, no real before and after
for B2), say so and replace it with another structure. Do not manufacture the missing input.

Length follows the platform: see `platform-limits.md`. The first visible lines of the body carry
the weight, because that is where truncation lands.

## 3. The three CTAs: a commitment ladder

| ID | Commitment | Typical job | Example verbs |
|---|---|---|---|
| C1 | Low | Learn or look, no data handed over | See, read, watch, compare |
| C2 | Medium | Trade contact details for something useful | Download, get, book a call, try |
| C3 | High | Ask to buy or to be quoted | Request a quote, start, order |

One label per intent. If the brand kit locks CTA wording, use the locked wording. The CTA line
in the copy and the platform's CTA button should not say two different things.

## 4. Screening rubric (50 hooks down to a shortlist)

Score each hook 0, 1 or 2 on each criterion, then sum. This is structured judgement. It does not
predict performance, and the output must say so.

| Criterion | 0 | 1 | 2 |
|---|---|---|---|
| Specific | Abstract or generic | Some detail | Concrete detail the user supplied |
| Stops the scroll | Blends into the feed | Mildly distinct | Would interrupt a skim in this feed |
| Claimable | Cannot be backed | Needs a source | Backed by what the user gave |
| Distinct | Near-duplicate of another hook | Same angle, new wording | Different angle from the rest of the shortlist |
| Fits the platform | Over the visible limit | At the limit | Lands inside the visible limit |
| Fits the audience | Wrong awareness stage | Plausible | Matches the audience's stated situation |

Selection rules:

1. Drop any hook that scores 0 on Claimable, whatever its total.
2. Take the top scorers, but keep at least four different angles in the shortlist so the first
   test compares ideas and not wordings.
3. Break ties in favour of the angle that is least represented so far.
4. The default shortlist size is 8 to 10. It shrinks to 3 or 4 when the budget cannot support
   more (see the test plan in `SKILL.md`).

---

## 5. Compatibility check before assembly

Before presenting assembled ads, check every pairing the user is likely to run:

- A hook that promises a specific figure must not sit above a body that contradicts it.
- A hook that asks a question must not sit above a body that opens by answering a different
  question.
- Proof-led bodies need hooks that do not overclaim relative to the proof.
- A C3 (high commitment) CTA after a pure curiosity hook is a mismatch worth flagging; offer C1
  or C2 for those pairings.

Record incompatible pairings in the matrix instead of deleting the hook or body.
